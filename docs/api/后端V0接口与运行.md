# 后端 V0：运行与前端接入

本接口只负责保存和读取发现。Python 3.12 标准库，无安装依赖。以 PowerShell 7 从项目目录运行：

```powershell
Set-Location D:\Agent_Desktop\Areas\workbench
./scripts/start-backend.ps1
```

默认服务 `http://127.0.0.1:8765`。数据：`data/workbench.sqlite3`（及 SQLite WAL/SHM），令牌：`data/api-token.txt`。Ctrl+C 停止，重新执行同一命令读取同一数据库。端口占用会明确退出，不自动改端口。可用 `-Port 8766 -DataDir './data-dev'` 隔离环境；同一数据目录仅建议启动一个服务。停用无需改 Harness，关闭本进程即可。

现已附带同源前端：直接打开服务根路径 `/`，在页面输入令牌即可。静态资源只开放 `/`、`/app.js`、`/app.css`，无任意目录浏览；数据 API 仍需认证。页面的令牌仅留在内存中，刷新后重新输入。当时的前端范围见 V0 历史记录（原工程历史记录）；当前入口见 前端维护与验证（原工程历史记录）。

若单独开发另一前端并运行在 `http://127.0.0.1:5173`，启动加 `-AllowedOrigin 'http://127.0.0.1:5173'`。只额外允许该精确 Origin（localhost 与 127.0.0.1 不互换），不带末尾斜杠。业务 API 请求附 `Authorization: Bearer <本地令牌>`，POST 还须 `Content-Type: application/json`。前端由本机用户提供令牌，在内存中保存，勿打包进代码或公开网页；预检 OPTIONS 无需令牌，业务请求仍需。默认只允许本机同源页面，无跨域授权。Host 必须是本机名及实际端口。

## 演示与测试

真实 Agent 发布现成的 v1 JSON，可调用正式客户端（复用同一 HTTP API）：

```powershell
./scripts/publish-discovery.ps1 -Payload '<现成发现JSON的绝对路径>'
$LASTEXITCODE
```

可用 `-Port/-DataDir` 指向同一服务；`-Attempts` 默认 3（1–5），`-Timeout` 默认 10 秒（1–60）。工具有界重试且保留同一文件字节；响应丢失后查同投递键并核对内容摘要；回执和详情读回成功后才输出 readback_confirmed=true。退出码 0=读回成功，1=本地输入或配置错误，2=确定错误需处理，3=无法确认需保留同键重试。非零不等于未提交，不应自动换键。详见 DSH 接入与真实验收步骤（原工程历史记录）。

启动服务后，另一个 PowerShell 窗口运行：

```powershell
./scripts/demo-publish.ps1
./scripts/test-backend.ps1
python ./experiments/20261030-backend-v0/smoke.py
```

演示发布 [publish-v1.example.json](publish-v1.example.json)，始终 is_test=true。重复演示返回 duplicate；真实列表默认不含它。demo 的 DataDir/Port 须与服务一致。自动测试使用独立临时数据库；smoke 在该实验目录新建 run-*，启动两个先后运行的真实服务进程、发布、运行 PowerShell 消费端、停止重启、复查回执和幂等，最后停止进程。不会接触正式 data 或 DSH。smoke 产物不包含真实来源或聊天，令牌只留在被忽略的隔离数据目录。

直接调用示例：

```powershell
$headers = @{ Authorization = 'Bearer ' + (Get-Content ./data/api-token.txt -Raw).Trim() }
$body = [IO.File]::ReadAllBytes((Resolve-Path ./docs/api/publish-v1.example.json).Path)
$receipt = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8765/v1/discoveries' -Headers $headers -ContentType 'application/json' -Body $body
Invoke-RestMethod -Uri "http://127.0.0.1:8765/v1/receipts/$($receipt.receipt_id)" -Headers $headers
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/v1/home' -Headers $headers
```

## 接口

所有正常响应有 schema_version=1。业务端点均需令牌。

| 方法与路径 | 行为 |
|---|---|
| POST /v1/discoveries | 发布一条发现，输入见版本化 JSON 样例 |
| GET /v1/receipts/{receipt_id} | 查询一次已持久化发布结果，不存在 404 |
| GET /v1/deliveries/{delivery_key} | 查询该键首次成功提交回执；解决响应丢失；未提交 404 |
| GET /v1/discoveries | 分页读取，默认排除测试记录，含全部修订版本 |
| GET /v1/discoveries/{record_id} | 详情、前后修订及完整历史 ID、来源可用性 |
| GET /v1/home | 重要变化空状态 + 上海今日发现 |
| GET /v1/health | 实际执行一次数据库读取后返回 status=ok |

列表参数：`limit` 1–100，默认 30；`before` 为上一页 next_before；`since` 包含、`until` 不包含，均为带时区 ISO 8601；`include_test=true` 显式包含测试样本。排序是接收序号倒序，时间过滤是 received_at，而不是生产者 generated_at。每页最多 100 条。首页只接受 limit/include_test；今日分页使用 today_discoveries.window 的 since/until 和 next_before 调用列表端点。返回 next_before=null 表示结束。

```json
{"schema_version":1,"items":[],"next_before":null,"order":"receive_sequence_desc","time_basis":"received_at","includes_revisions":true,"window":{"since":null,"until":null}}
```

首页结构：`timezone="Asia/Shanghai"`、`date="YYYY-MM-DD"`、`important_changes=<真实open事件数组>`、`important_changes_state="ready"`、`important_changes_page={next_before,order}`、`today_discoveries=<上述分页模型>`。重要变化接口及知晓/稍后语义见 [收件箱说明](重要变化V0接口与运行.md)。发现列表是不可变版本流；revision_of/root_id 用于区分新发现与修订，详情中 superseded_by 指向后继。首页或列表为空是正常状态，不填充示例卡片。客户端显式刷新即可，无推送。

## 输入约束与身份

顶层 schema_version 必须为整数 1、delivery_key 为稳定投递键、discovery 为完整对象；拒绝未知字段。发布最多 128 KiB，UTF-8 JSON，拒绝重复键、NaN 和 Infinity。

record_id、delivery_key、run_id、各 session ID 等标识最多 128 字符，以字母/数字开始，其余仅字母/数字/`_.:-`。title 最多 300 字符，excerpt 与 interpretation 各最多 16000 字符，不能为空；generated_at 必须包含时区，后端规范化为 UTC；is_test 必须为布尔。时间与摘要的规范化在摘要计算前执行。完全重投应保留整个请求内容，不要刷新 generated_at/run_id。

source.type 为 zotero_pdf/local_pdf/unknown；其余字段可缺省或 null，不补造：parent_key、attachment_key、64 位十六进制 sha256、从 1 起的整数 pdf_page（上限 1000000）、可选 printed_page（最多 64 字符）、local_path。指纹声明不会触发后端哈希读取。路径必须为本地 Windows 绝对盘符路径，拒绝 UNC、设备路径、ADS、保留名、控制字符和 ..；仅在详情读取时查询文件是否存在，不提供下载或执行入口。

producer 必须有 harness、profile、working_directory、run_id、production_session_id、main_session_id；可有 main_session_title（最多 300 字符）。working_directory 为绝对本地路径。子会话 ID 与准确主会话 ID 分开提交；无法确定主会话时先补充证据，不能用子会话或 --last 代填。后端保存声明，不声称核验了原生会话。

verification.mechanical 的 status 为 pass/fail/not_checked，scope/evidence 为文本或 null（各最多 4000 字符）；verification.semantic 的 status 为 confirmed/rejected/not_reviewed，reviewed_by 为文本或 null（300），evidence 为文本或 null（4000）。这两个对象及其子字段必须完整，避免把字段缺失解释成成功。

## 幂等、修订与回执

同一 delivery_key 同一规范化内容：duplicate；同键不同内容（含 SHA 变化）：409 delivery_conflict。同一 record_id 同内容，即使用新投递键也 duplicate；同记录不同内容：409 record_conflict。SHA 改变若是新发现用新 record_id；若是修订则新 record_id + revision_of，不会静默吞掉。

修订目标必须存在且尚无后继。is_test、source 的 type/parent_key/attachment_key/local_path，以及 producer 的 harness/profile/working_directory/main_session_id 必须与目标一致。SHA、页码、摘录、解释和生产 run/子会话可变化。来源身份或主会话改变应提交独立新记录。一个目标的并发修订仅一个成功，另一方取当前后继并人工判断如何处理；不自动合并。历史不可修改、删除，旧回执保持原样。

```json
{
  "schema_version": 1,
  "receipt_id": "持久化回执 UUID",
  "status": "accepted",
  "record_id": "demo-record-001",
  "delivery_key": "demo-delivery-001",
  "content_sha256": "规范化完整内容的 SHA-256，实际为64位十六进制",
  "recorded_at": "2026-10-30T04:00:00.000000+00:00",
  "persistence": {"receipt": true, "discovery": true},
  "error": null
}
```

accepted 为 201；duplicate 为 200，每次响应有独立已存回执，投递键查询始终返回首次成功回执。rejected 表示本次提交未写入发现，422（字段/版本/路径）或 409（投递/记录/修订冲突）；通常能持久化拒绝回执。failed 为 503、retryable=true；discovery=null 表示结果未知，先查询 delivery_key 或原样重投。若无法保存回执，receipt_id=null、persistence.receipt=false。不要在错误后换键盲投。

错误原因在 error={code,message,retryable}。协议错误（401/403/404/400/411/413/415）及读取错误不保证有持久化发布回执；可解析到的非法发布 JSON/业务输入会尝试保存 rejected 回执。网络中断也不代表未提交，须保留同键重试。receipt/discovery=true 只证明数据库提交，不说明页面已展示、文件已打开或用户已阅读。

## 前端必须保留的证据边界

- 原始摘录和解释分别展示，received_at/generated_at 分开标注；所有文本作为纯文本呈现，勿使用 innerHTML 渲染输入。
- verification 是生产者声明；backend_verification 单独给出 schema=pass、source_hash/excerpt_page_match=not_checked、semantic=not_reviewed、reviewer_authenticated=false、verified=false。生产者即使声称 confirmed 并填写人名，也不能显示“人工已认证”或“已验证”；rejected 保留拒绝标签。
- source_locator 仅详情提供：not_provided、missing、inaccessible、exists_unverified（存在但未核对 SHA/页码）或 not_checked_on_this_platform。缺失来源不删除发现。source 中原路径、Zotero 键、页序都保留；不显示假成功的打开按钮。
- session_locator.status=manual，url=null。以 harness/profile/working_directory/main_session_id 手动定位，production_session_id 仅追溯生产身份，不代替主会话。

本阶段未实现人类审阅认证、精确会话深链或 PDF 自动跳页。正式 HTTP 发布工具已提供，真实 DSH 尚未完成联调；前端已有独立本地联动验证，不能代替真实生产链路和原生入口验收。
