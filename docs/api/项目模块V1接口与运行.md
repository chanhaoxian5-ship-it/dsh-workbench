# 项目模块 V1 接口与运行

2026-10-30。当前数据库版本3，HTTP schema_version仍为1。Python3.12标准库运行，无新增运行依赖。先停止旧服务，再执行 `./scripts/start-backend.ps1`；原数据库按事务加法升级。服务、令牌和同源保护沿用[原说明](后端V0接口与运行.md)。

## 统一读写规则

项目写入有统一外壳：

```json
{
  "schema_version": 1,
  "operation_key": "stable-operation-key",
  "expected_version": 0,
  "item": {
    "id": "stable-item-id",
    "kind": "artifact",
    "title": "计划原件",
    "archived": false,
    "data": {
      "relative_path": "PLAN.md",
      "category": "document",
      "description": "原目录引用",
      "expected_sha256": null
    }
  }
}
```

新建expected_version=0；修改使用刚读到的登记version；item.id稳定且不能改变kind。修改后新增登记修订，旧修订仍可查。归档使用archived=true，不硬删除。相同操作键/内容重试返回原回执（HTTP200，回执status保留原值）；相同键不同操作类型、目标或内容为409。不要更新请求键或改内容来“解决”超时。

登记空间时外壳的item改为workspace，必填id/name/root_path/kind/view/status/favorite/description/is_test。kind=project/area，view=paper/plan/software/general，status=active/paused/archived。目录为Windows本地绝对路径，root_path与is_test在登记后不可改。同一目录不能重复登记。登记不创建或搬迁目录，不检查所有文件。

## 路由

| 方法与路径 | 行为 |
|---|---|
| GET/POST /v1/workspaces | 分页列空间；登记或更新空间 |
| GET/POST /v1/workspaces/{w} | 读空间及历史；更新此空间 |
| GET /v1/workspaces/{w}?version=N | 查询旧登记修订，附current_version |
| GET /v1/workspaces/{w}/overview | 真实记录计数、最近修改；不推断整体完成 |
| POST /v1/workspaces/{w}/refresh | 只读指定顶层来源，保存读取快照 |
| GET/POST /v1/workspaces/{w}/{collection} | 列出/保存该类资料；sources禁止外部直接POST |
| GET /v1/workspaces/{w}/{collection}/{id} | 当前详情、current_version和修订历史 |
| GET 上一路径?version=N | 读取确切旧修订 |
| GET /v1/workspaces/{w}/artifacts/{id}/inspect | 核对当前文件存在、大小、完整指纹及匹配状态，可带version |
| GET /v1/workspaces/{w}/artifacts/{id}/preview | 只读有上限的Markdown/DOCX纯文字；其余格式明确降级 |
| GET /v1/workspaces/{w}/compare?left=A&right=B | 比较整稿版本的固定文件引用 |
| GET 上一路径&left_artifact=X&right_artifact=Y | 可选比较两侧有指纹依据的纯文字，缺失或不符则明确不可核实 |
| GET /v1/project-items | 跨已登记空间查询项目资料，不扫描磁盘 |
| GET /v1/search?q=... | 搜索登记资料和来源文本片段 |
| GET /v1/project-operations/{key} | 原操作的持久化成功回执 |
| GET /v1/receipts/{receipt_id} | 与原模块共用回执查询 |
| GET /v1/capabilities | 已实现模块及手动定位边界 |

collection为artifacts/versions/feedback/plans/tasks/records/canvases/sources。列表默认limit30，1..100；before游标分页；默认排除测试，显式include_test=true包含。资料列表默认排除archived，include_archived=true可包含。工作空间列表可带status=all/active/paused/archived；项目资料列表可带kind与workspace_id（跨空间路由）及q。搜索q必填，最长200字符，按普通文本匹配；不扫描原文件和原生会话。

按注册序号倒序分页；更新原条目不改变该注册序号。分页不是跨请求冻结快照，内容或状态变化后可从第一页刷新。详情按明确ID查询，直接读取测试对象是显式访问，不等同于其进入默认真实列表。

## 每类资料的data

所有字段按下表必填，允许空字符串或null处另行标注；拒绝未知字段。正文摘要上限12000字符，其余多数说明4000，标题300。示例见[完整请求样例](project-v1.examples.json)。

| kind | data字段与规则 |
|---|---|
| artifact | relative_path（目录内相对路径）、category=document/figure/table/code/other、description、expected_sha256=null或64位SHA |
| version | label、status=draft/in_review/submitted/archived、summary、refs；previous最多一个且创建后不能改写 |
| feedback | quote、response、status=pending/in_progress/addressed/rejected、location、refs；恰好一个version关联；addressed须说明、位置、证据 |
| plan | summary、stage、next_step、refs、change_ids；至少一个source引用，变化须存在且测试分类一致 |
| task | summary、status=todo/doing/blocked/done/cancelled、due_date=null或YYYY-MM-DD、refs；恰好一个plan，depends_on不能成环 |
| record | summary、stage、next_step、blockers字符串数组、refs、session=null或准确会话锚点 |
| canvas | zoom=0.1..4、layer=formal/explore、nodes最多200、edges最多400；数值有限、端点存在 |
| source | 只允许服务器refresh创建，含relative_path/status/sha256/text/truncated/read_at；语义不自动解析 |

引用形如 `{id:"artifact-1",kind:"artifact",role:"evidence",version:1}`；version可在写入时省略，服务器在事务内解析为当前修订并固定保存。目标须存在于同一工作空间，类型匹配；引用明确的旧修订不会随目标后续修改漂移。

2026-11-03复核修正：一个整稿版本中同一artifact ID最多出现一次（role=artifact），不能混入该文件的两个修订，也不能重复引用同一修订。否则409 `ambiguous_artifact_reference`，不保存操作或回执。旧版本若已含这种歧义，compare同样明确409，不再用字典静默覆盖；历史登记保留，需明确选择后以新修订纠正。画布多个节点重复引用同一资料仍允许。

引用role按资料类型限制：整稿版本用artifact/previous；反馈用version/evidence/context；计划用source/context；任务用plan/depends_on/source；工作记录用source/context/evidence。canvas节点ref使用同结构或null自由草稿。canvas节点字段id/x/y/label/ref；边字段id/from/to/label。工作记录session字段为harness/profile/working_directory/main_session_id，不造链接、不填最新会话。

source刷新请求使用外壳 `{schema_version:1,operation_key,expected_version:<空间登记版本>,filenames:["README.md","PLAN.md"]}`。只接受4个固定来源名称，每次读取最多1MiB/文件，保存完整指纹与最多12000字符文本；缺失和不可访问同样有明确快照，不伪造摘要。

## 回执、错误与实际边界

成功回执含schema_version/receipt_id/status/delivery_key（本次operation_key）/content_sha256/recorded_at/error，另含workspace_id、operation和resource={id,kind,version}；来源刷新resource={kind:"source_refresh",items:[...]}。persistence={receipt:true,project_state:true}。摘要包括操作类型和目标空间，不是源文件指纹。

首次新建通常201，编辑、重复与刷新200。422输入或引用用途不符，404对象不存在，409版本/请求键/目录冲突、依赖成环、来源关系不相容，503存储结果未确认。错误响应不保存项目拒绝回执；成功提交后响应丢失时先GET project-operations或同键原样重投。任务done、反馈addressed和整稿submitted均为登记声明，不代表真实项目验收或实际投稿。

文件核对最多64MiB，读取中变化不算成功；路径跳转、重解析点/符号链接拒绝。Markdown和DOCX只返回最多12000字符纯文字，DOCX文件读取最多8MiB、document.xml最多2MiB；不保留格式、不执行嵌入内容。PDF继续用原工具手动定位。可选文字差异要求两侧文件均匹配预先登记的指纹，最多300行，truncated明确标注；否则返回historical_content_unverifiable。

## Agent发布与维护

每份文件只放一个完整请求外壳。调用沿用同HTTP接口的可靠客户端：

```powershell
./scripts/publish-project.ps1 -Collection workspaces -Payload '<空间登记请求.json>'
./scripts/publish-project.ps1 -Collection artifacts -Workspace '<空间ID>' -Payload '<文件引用请求.json>'
```

支持workspaces、refresh及其余可写collection。可配置Port/DataDir/Attempts；只读一次请求文件，保存同操作键重试，核对持久化回执并读取确切登记修订后才报告readback_confirmed=true。退出码0成功、1本地输入配置问题、2确定错误需处理、3结果未确认。日志不输出令牌或全文。

```powershell
./scripts/maintain-backend.ps1 -Action check -Source ./data/workbench.sqlite3
./scripts/maintain-backend.ps1 -Action backup -Source ./data/workbench.sqlite3 -Destination ./backups/workbench-20261030.sqlite3
./scripts/maintain-backend.ps1 -Action restore -Source ./backups/workbench-20261030.sqlite3 -Destination ./data-restored
./scripts/start-backend.ps1 -DataDir ./data-restored
```

备份使用SQLite一致备份接口，可包含运行时已提交WAL状态；拒绝覆盖已有目标。恢复要求全新目录，不复制令牌，新启动生成新令牌。只备份工作台数据库，不备份原项目文件。服务停止后也可备份，但运行中不能只复制sqlite主文件。
