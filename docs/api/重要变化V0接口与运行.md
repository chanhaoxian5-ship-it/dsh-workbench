# 重要变化 V0 接口与运行

2026-10-30。沿用原服务启动命令、端口、Bearer token、Host/Origin 保护与 128 KiB POST 限制，无新依赖。需停止旧进程后启动新版以加载代码和数据库加法升级（user_version 1→2）。实现决策（原工程历史记录）。

## 发布与更新

先通过既有发现接口保存摘录、解释、来源、生产者与准确会话锚点，再发布事件引用。不要把所有发现都推为重要变化。初次创建 expected_version=0；事件身份由生产者稳定提供。

```json
{
  "schema_version": 1,
  "delivery_key": "change-delivery-001",
  "change_id": "change-001",
  "record_id": "demo-record-001",
  "expected_version": 0,
  "priority": "high"
}
```

POST `/v1/changes`，priority 为 normal/high；所有字段必须存在，拒绝未知字段。引用的发现必须存在；测试分类、来源及会话核验状态均由引用发现继承，不能在事件中伪造“已验证”。上例引用演示发现，因而也是测试事件，默认不会显示。

更新先提交新的发现修订，再用新 delivery_key、相同 change_id、较新的 record_id 与当前 expected_version 发布。只允许同一发现修订链，不允许倒退到更旧的依据；不同来源的工作可建立独立事件。新引用或优先级变化会增加事件 version，并重新进入 open。相同引用/优先级换键重投返回 duplicate，不重开已知晓事件。

## 接口与状态

| 方法与路径 | 用途 |
|---|---|
| POST /v1/changes | 创建/更新事件引用 |
| GET /v1/changes | 当前事件分页；默认 state=open、排除测试 |
| GET /v1/changes/{change_id} | 当前事件、discovery 依据与 history 证据版本历史 |
| GET /v1/change-deliveries/{delivery_key} | 查询该发布操作的持久化成功回执 |
| POST /v1/changes/{change_id}/state | 设置注意力状态 |
| GET /v1/receipts/{receipt_id} | 与发现共用的持久化回执查询 |
| GET /v1/home | important_changes 为实际 open 事件 |

列表参数 limit=1..100（默认30）、before=上一页 next_before、include_test=true/false、state=open/known/later/all。返回 `{schema_version:1,items:[],next_before:null,order:"latest_change_sequence_desc",state:"open"}`。每项有 change_id、record_id、root_id、priority、version、latest_seq、state、state_version、updated_at、discovery；详情额外有 history（版本、引用、优先级、接收时间）。discovery 保留原有核验与会话定位边界。

首页 important_changes 数组仍保留，新增 important_changes_page={next_before,order}；翻页用 GET /v1/changes。important_changes_state=ready 代表模块可读取，不代表已有事件或自动监测。首页变化不限制为“今日”，尚未知晓的旧变化也会保留。

用户状态操作示例：

```json
{
  "schema_version": 1,
  "action_key": "attention-action-001",
  "expected_version": 1,
  "expected_state_version": 1,
  "state": "known"
}
```

POST `/v1/changes/change-001/state`。known=知道了，later=稍后分组，open=重新关注。操作键须稳定；响应丢失后原样重投会拿到原回执，不会覆盖后来更新的状态。状态提交不修改发现、不调整计划或完成任务；later 没有定时唤醒。version 或 state_version 冲突返回 409，重新读取后由用户判断。

## 回执和错误

首次发布/内容更新 201，用户操作或同内容换键 200。成功回执沿用 schema_version/receipt_id/status/record_id/delivery_key/content_sha256/recorded_at/error，另有 change_id/version/state/state_version/operation。operation=publish/state；persistence={receipt:true,change:true}。content_sha256 为本操作内容摘要，不是引用发现的摘要。state 操作回执中的 delivery_key 对应 action_key。

**同操作键重投返回最初回执**（HTTP 200，回执 status 保持原值），不创建新回执、不重放动作；回执里的状态代表当时提交结果，当前状态应查事件详情。发现原有的重复回执语义保持原样。发现投递键、变化投递键和变化状态键各自独立命名空间。

422 表示字段/版本输入错误；404 表示事件不存在；409 可能是 operation_conflict/change_conflict/state_conflict/evidence_not_found/incompatible_change/stale_evidence。错误响应沿用 error={code,message,retryable}，变化写入的拒绝不保存拒绝回执。SQLite 故障返回 503，结果可能已提交，查同投递键或原样重投。协议错误沿用原接口。

正式 `publish-discovery.ps1` 仍只提交发现；事件请求直接调用同一 HTTP 服务，不能把事件 JSON 传给该脚本。以下片段可在发现已提交后使用：

```powershell
$headers = @{ Authorization = 'Bearer ' + (Get-Content ./data/api-token.txt -Raw).Trim() }
$body = @{schema_version=1;delivery_key='change-delivery-001';change_id='change-001';record_id='demo-record-001';expected_version=0;priority='high'} | ConvertTo-Json
$receipt = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8765/v1/changes' -Headers $headers -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
Invoke-RestMethod -Uri "http://127.0.0.1:8765/v1/receipts/$($receipt.receipt_id)" -Headers $headers
```

前端首页提供三个分组、加载更多及依据详情。操作失败时重新读取确认状态；新内容与旧操作冲突时保留新变化。预览模式不发送状态写请求；断开后清空真实变化卡片。
