# 项目凭证与浏览器登录（2026-11-04）

本轮将管理员连接与 Agent 的项目访问分开。插件版本 0.3.0，HTTP schema_version 仍为 1，项目数据库结构仍为 3。仅服务重启后加载新代码；本轮没有修改日常 DSH profile 或真实项目目录。

## 用户操作

1. DSH 设置 → Workbench → 启动 → 准备打开工作台 → 打开工作台。30 秒一次性票据换取浏览器会话，不再向网页脚本返回管理 Token。
2. 浏览器会记住连接。闲置 30 天或创建满 90 天失效；可从连接设置明确退出，服务端撤销这次登录。刷新和后台轮询不续期，页面可见时的真实键鼠/滚动操作每分钟最多续期一次。
3. 网页顶部“项目访问权限”选择已登记的项目，填写名称并选择只读/读写，点击“生成并写入项目连接配置”。这是一次明确写入，会在选择的原目录下创建 `.workbench/project.json`。
4. DSH 设置中填写同一个项目的绝对目录，生成此项目的 MCP 配置。DSH 工具调用传 `project_dir`；已带 `--project-dir` 的 MCP 无须逐次传入。
5. 凭证管理显示名称、项目、权限、最近使用、最晚到期和有效状态，可逐个撤销。同目录重新生成会替换连接配置并撤销原配置对应的凭证，不保留两把仍可用的旧钥匙。

## 权限与期限

| 凭证 | 适用范围 | 闲置失效 | 最长有效期 |
|---|---|---|---|
| 管理 Token | DSH 宿主启停、签发启动票据；人工首次网页登录 | 保留旧机制，不自动过期 | 人工更换 |
| 浏览器会话 | 本机管理员界面，含凭证管理 | 30 天，无交互读取不续期 | 90 天，重新从 DSH 打开登录 |
| 项目凭证 | 一个稳定 workspace_id，read 或 write | 默认 90 天，合法调用续期 | 默认 365 天，更换凭证 |

管理 API 可把项目 idle_days、lifetime_days 各设为 1–365 整数天。界面目前用默认值。write 包含 read，不能更改工作区根目录、创建其他工作区、控制服务或管理凭证。项目凭证的全局列表与搜索强制过滤 workspace_id；跨项目 ID、引用和回执不允许读取。全局 home/discoveries/changes 尚未建立项目归属，项目凭证返回 403；不能用复制管理 Token 的方法绕过。

旧全局发现 MCP 工具名保留兼容，但在项目凭证模式下不可用。项目 Agent 交付文件、阶段、版本、计划、任务和工作记录；全局发现的项目归属需要后续独立设计。

## 文件与秘密

项目内的 `.workbench/project.json` 仅含：schema_version、service_id、workspace_id、credential_id、data_dir。不含 Token，不含固定端口。该文件含本机路径，建议作为本机配置排除于版本控制；不要把复制此配置当作授权另一个目录。

服务数据目录保存：

- `api-token.txt`：兼容现有管理控制器的管理秘密，只给宿主使用，不给普通项目工具。
- `auth.sqlite3`：服务身份和凭证摘要、范围、时间、撤销状态，不保存 Token 明文。
- `credentials/<credential_id>.secret`：本机 Agent 必须取用的秘密。Windows 使用当前用户的 DPAPI 加密，POSIX 使用 0600 文件权限。该目录不要同步、发布或提交。
- `endpoint.json`：运行实例地址与身份，不含秘密。重启换端口无需更新项目配置。

Agent 只读取项目配置指定的凭证；校验服务 ID、运行实例、工作区 ID 和注册根目录，禁止回退读取 `api-token.txt`。配置复制到另一个项目目录会被拒绝。SQLite 一致备份仍只备份项目记录；恢复到新目录必须重新签发访问凭证，不能宣称已备份登录状态。

## HTTP 契约

全部需要 Host/Origin 检查。Bearer 管理或项目凭证仍支持原客户端；浏览器使用 HttpOnly、SameSite=Strict Cookie。Cookie 请求必须带 `X-Workbench-Request: 1`，跨站表单/简单请求不能借 Cookie 操作。页面不把秘密存入 localStorage/sessionStorage。Cookie 未使用 Secure，因为当前明确运行在本机 HTTP；不把该方案直接搬到远程部署。

| 方法与路径 | 身份 | 请求/结果 |
|---|---|---|
| POST `/v1/auth/session` | 管理 Bearer | `{}` → Set-Cookie；不会返回 Token |
| GET `/v1/auth/session` | 已登录 | 返回连接状态与会话策略，不续闲置时间 |
| POST `/v1/auth/activity` | 已登录 | `{}` → 延长闲置期限，绝对期限不变 |
| POST `/v1/auth/logout` | 已登录 | `{}` → 撤销当前会话并删除 Cookie |
| GET `/v1/auth/projects` | 管理员 | 凭证元信息，不含秘密或摘要 |
| POST `/v1/auth/projects` | 管理员 | `{workspace_id,label,permissions,idle_days?,lifetime_days?}` → 写入目录配置，返回 credential_id/config_path/workspace_id |
| POST `/v1/auth/revoke` | 管理员 | `{credential_id}` → 即时持久撤销，删除对应本机秘密文件 |

`/v1/runtime/connect` 仍接受一次性 ticket，但响应改为 `{schema_version:1,connected:true}` 加 Cookie，不再返回永久 Token。旧版网页引导不可与新版后端混用。

## 边界

这是单用户本机接口的最小授权机制，不是不同 Windows 用户或敌对本机程序之间的沙箱。同一 OS 用户下有任意文件和代码执行权限的 Agent 仍可能调用 DPAPI 或读取管理秘密。Cookie 不以端口隔离；服务使用独立 Cookie 名区分资料库，但恶意本机 HTTP 服务仍在本机信任边界内。跨设备、多人或公网部署需重新设计传输、身份和密钥存储。
